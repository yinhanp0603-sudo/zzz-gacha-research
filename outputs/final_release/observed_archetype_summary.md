# 公开队伍主核锚定与机制标签

为 **60** 名角色建立标签，覆盖 **2,876,445** 条合格战斗记录、**6,678** 种原始组合。合法完整三人记录 **2,866,763** 条。

## 维表与组合表

- [dim_observed_archetype.csv](dim_observed_archetype.csv)：每角色一行，保留原始英文标识、游戏 ID、中文名、官方职业、社区定位、研究主核角色与机制证据。

- [observed_comp_archetype.csv](observed_comp_archetype.csv)：每个无序原始组合一行，保留重复成员、异常标签与出场数；不以出现频次筛掉罕见混搭。

职业由角色字典映射，并与 Enka 职业核对；社区 dps/subdps/support 是主输出、体系引擎、泛用插件的研究初始化，不等于官方队伍流派，也不识别战斗中的实际伤害份额。耀嘉音、凯撒、妮可、莱特、柚叶固定为 Flex / Support。

规则版本 `observed_archetype_v1`，资料口径日期 2026-10-28。35 个主核／引擎中，24 个的特殊机制已按技能文本核对，其余 11 个保留职业能力族基线；不据此推定具体失衡或异常结算事件。这套标签不逐历史版本复原技能平衡调整。


## 组合判定

核心签名包含所有主输出与体系引擎的游戏 ID、职业和机制族，按 ID 排序；不包含泛用插件。多核全部保留，双普通强攻也不合并成一个主核。更换普通插件不改变签名。纯插件队记为 `no_core`；未收录角色、邦布、数字标签归为 `invalid_identifier`，不猜成角色。

不足三人的合法角色队伍仍可带主核签名，但与合法完整三人分析分母分开；重复成员和无效标签保留质量状态与次数。蕾米埃尔只有在完整互异三人队且三个角色官方职业均为异常时标“耀变三异常”，否则为“耀变非三异常”。

| --- | --- | --- |

## 机制族定义

这些是基于职业能力和技能文本建立的分析族。仅有名单不能证明失衡、紊乱、异放、追加攻击或其他条件在该场战斗实际触发；具体能力与条件见 `mechanism_tags` 和每角色证据。

| 机制族 | 定义 |
| --- | --- |
| 常规直伤 | 职业级直伤能力族，未据此断言必须依赖失衡窗口。 |
| 常规失衡 | 技能文本存在明确失衡增伤或失衡窗口消耗；不表示其他输出仅发生于失衡期。 |
| 异常伤害/积蓄 | 异常伤害与积蓄能力族；不据阵容直接断言紊乱已触发。 |
| 紊乱异放 | 特殊紊乱、异常联动与异放的分析汇总族；具体是否拥有异放由mechanism_tags区分。 |
| 追加攻击 | 技能明确将核心输出判定为追加攻击；后台伤害或支援攻击不自动归入此类。 |
| 贯穿 | 主要招式具有贯穿伤害；不将穿透率或减防等同贯穿，也不把所有异常结算都称为贯穿。 |
| 帷幕无视失衡 | 主要伤害将失衡易伤改由帷幕易伤结算；仅出现帷幕关键词不足以归类。 |
| 耀变体系 | 蕾米埃尔的耀变和异常异化；组合是否三异常由实际Anomaly人数单独判断。 |
| 锐化防御 | 锐化伤害按防御倍率和锐暴结算；不同于防护职业或普通减防。 |
| 泛用辅助 | 不作为流派定义核，保留官方职业和可核对的辅助能力。 |

## 来源与复现

- [分类规则及技能证据](../../tools/observed_archetype_rules.json)；[构建脚本](../../tools/build_observed_archetypes.py)。

- 统计仅来自已有 `observations/observations.sqlite` 的 `is_eligible=1` 记录；SQLite 使用 `mode=ro` 和 `query_only=ON`，不重导入、不建索引，数据库文件身份、长度、修改时间未改变。

- 本轮仅从既有 6,678 个组合的 `comp_units` 与 `eligible_records` 刷新标签和展示，未重新读取观测库；原查询及组合汇总耗时 **56.64 秒**。

- 规则语义检查覆盖插件替换、命破辅助适配、顺位、双核、纯插件、异常标识、不满三人与三异常条件。

- 同一个机制标签可存在于多个主核或组合中，不能把重叠标签的记录数相加当作总量；社区成功通关样本的流派占比不代表全部玩家持有率、通关成功率或因果强度比较。
