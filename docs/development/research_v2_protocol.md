# 机制锁与售后支援：研究协议 v2

研究问题：在《绝区零》这类抽卡动作游戏中，运营方以机制锁强度 λ 和售后支援强度 a 管理数值膨胀时，老角色的保值寿命、玩家囤抽和付费意愿，以及固定初始玩家队列的长期现金与留存怎样变化？

这是以公开通关成绩提供条件观测锚点的反事实情景实验。λ、a 是模型内的干预，不是从公开样本识别出的官方运营参数。

## 1. 实验入口与产物隔离

入口：`config/research_v2/experiment.json`。

执行器：`tools/run_research_v2.py`。

产物：`outputs/research_v2/`，包含独立运行数据库、逐期与跨种子汇总、固定战斗轨迹、老资产结果和 `REPORT.md`。报告配套四张 SVG 展示机制锁与收入/留存、模块分离对照的逐期变化；`tables/parameter_registry.csv` 登记基准配置各参数来源。既有 `outputs/final_release/` 继续对应其原科学配置，公开样本不重复下载、导入或清洗。

运行数据库沿用项目已有 `config_id` 和 `run_manifest`。恢复执行时，仅复用科学配置、种子、完成状态及日志口径相同的运行；不同配置使用独立输出目录，不覆盖已有运行。模型公式与算法版本变化按项目身份约定生成新的 `config_id`。

## 2. 干预与公平对照

候选参数来自研究配置的 5×5 网格：

| 维度 | 档位 | 机制含义 |
|---|---|---|
| 机制锁强度 λ | 0、0.5、1、1.5、2 | 当期机制与主输出/体系的匹配惩罚；贯穿不等于自动对口 |
| 售后支援强度 a | 0.8、1、1.2、1.4、1.6 | 相对可用旧辅的配对数值净增益；机制适配提升独立固定 |

全部候选共用 HP 与主输出基准增长、同一首发目录与出场顺序、价格、免费资源、月卡权益、抽卡规则和初始人口。参数 a 只改变商品效果，不额外赠送角色或增加支援供给；λ 只改变机制惩罚，不同时提高 HP 增长。

研究参数的证据类别分别记录，避免把整组公式写成实证估计：

| 参数 | 本轮值或来源 | 证据类别 |
|---|---|---|
| 公开机制/非对策与对策成绩、专拐与替代辅助成绩 | `outputs/final_release/empirical_knob1_boss_lock.csv` 与 `empirical_knob2_support_lift.csv` | 条件观测，受玩家、配装与选择等混杂影响 |
| 输出窗口锁指数惩罚、数值壁垒惩罚 | 0.32、0.9 | 显式情景假设，不由公开得分比拟合 |
| 强/弱耦合专拐净增益 | 0.23、0.05 | 参考公开条件成绩范围的情景取值，不是角色因果伤害增益估计 |
| 角色机制适配、支援配对和适配提升 | 研究商品目录 | 显式情景假设 |
| 疲劳到续订、直购和流失的各项系数 | 行为配置 | 显式情景假设；公开成功战斗记录不含这些行为结果 |

a 仅缩放配对的数值净增益；支援的机制适配提升不随 a 同步变化。这样可分别观察“卖更高倍率”与“提供破壁能力”的作用通道。

四角 `(λ=0,a=0.8)`、`(0,1.6)`、`(2,0.8)`、`(2,1.6)` 用于解释边界情景。网格中间点用于识别有限候选内的收入—留存取舍，不把四角直接称为现实运营方案，也不预设哪种策略最优。

## 3. 时间、人口与随机对照

统一采用每期 42 天。20 期首发与环境目录覆盖两轮机制更替和售后周期，10 期实验读取同一目录的前缀，避免短长期使用不同商品排期。

默认规模为 200 名初始玩家，每个配置分别运行种子 1101、9101。前者属于配置中预先登记的筛选种子，后者属于独立复核种子。默认是可审阅的首轮实验，不据此宣称种子波动已被充分估计。扩大到预定的 5 组筛选 + 3 组独立复核，或 1000–3000 名玩家时，直接传入规模与种子参数。

玩家编号、时间索引和决策事件索引确定共同随机数。候选参数、处理顺序或一个情景多抽几次，均不得改变其他事件的随机键。人口增加只增加新编号，既有玩家的初始属性不重新洗牌。

20 期实验结束仍可用的资产按右删失处理。晚出道角色天然随访较短，主结论优先比较相同出道队列和相同投资/养成方案。

## 4. 战斗与付费行为的 2×2 分离对照

基准点固定 `λ=1,a=1`，商品目录、人口与时间相同：

| 战斗模型 | 付费行为模型 | 回答的问题 |
|---|---|---|
| v1 | v1 | 旧秽盾代理与固定付费意愿的参照 |
| v2 | v1 | 仅替换机制匹配与支援净收益后，结果怎样变化 |
| v1 | v2 | 仅加入疲劳驱动的续订/直购意愿后，结果怎样变化 |
| v2 | v2 | 战斗与付费回路的共同作用 |

v1 战斗分支沿用 `防御加成=0.8λ`、`非贯穿减伤=0.25λ`；v2 分支读取独立机制匹配参数。v1 行为分支沿用其原付费决策；v2 分支在保留原有支付能力上增加动态意愿。该分离对照不是既有最终报告的逐字复算，因为它使用本研究统一的 20 期商品目录。

## 5. 老资产的三类结果

### 自然寿命与维护寿命

Layer 2 固定主输出、影画/专武、驱动盘养成路径，分别计算不配限定支援与各支援出道即加入的同条件轨迹。支援对该主输出没有适配关系时，也保留其实际零收益结果。

首次 `CI<1` 是首次失效事件；首次观测即不达标可为 0 天，不强行改为正寿命。后续因养成或支援恢复满星是独立的恢复事件，不能抬高已经发生的首次失效时间。

每条轨迹同时报告首次失效/删失天数、恢复时点、累计满星期数、总观测期数和期末 CI。同条件配对报告专拐新增满星期数；仅当两侧均已发生首次失效时，报告测得的首次失效天数差。

### 玩家全库存结果

四角与基准使用全量日志，追踪仓库中所有历史持有角色。分别保留实际活跃时的可用性、部署情况、专拐配置与退坑冻结配置反事实可用性。活跃期首次失败、含退坑冻结配置随访的首次失败和失败所属情境分别记录，期末持有者状态取实际期末活跃状态。首次失败后恢复不会重置寿命。

L3 的购买由玩家状态决定；“买了支援的玩家后来更好”不能代替 L2 同条件配对证据。原始强度较高、支付能力较强或卡关更深都可能改变购买概率。

### 维护支出

分别报告支援池实际抽数与该池按需直购现金。免费囤抽、月卡权益和直购不混成现金，订阅收入也不重复计入每个角色。

同一支援可能服务多个主输出，因此支援池总支付不重复分配给多个资产。单资产延寿价格若需估计，应另行设计固定钱包的配对购买实验；本轮不把观察到的玩家支出解释为该角色的因果维护成本。

## 6. 行为、现金与留存口径

初始预算层描述支付能力与人口分组，在整个运行内固定。订阅意愿、直购意愿和是否仍活跃是三个独立状态。

续订/直购决策使用进入本期前已经形成的疲劳和连续失败，再结合当前补强机会；本期 Post-Eval 后更新疲劳与最终流失。停氪不没收已有资源、角色和保底；拒绝付费但继续活跃单列，不计为退坑。

主要经济结果为固定初始队列的累计订阅现金、累计直购现金和二者合计，单位元。人均现金始终除以初始人数，不除以幸存者。核心层留存始终使用初始核心层人数为分母，不把停氪玩家移出该分母。

囤抽结果保留当期免费、历史免费、订阅和直购四来源消耗，以及免费与订阅资源的独立期末库存。续订和直购意愿分别输出门控概率、允许/拒绝事件及拒绝付费但期末仍活跃的人期。

## 7. 搜索、复核与解释

收入和核心留存分别计算候选排名、筛选—复核 Spearman ρ，并保留每个独立运行的实际结果。不合成单一总分，不以“收入极差需要变大”作为模型标定目标。

对每个独立种子分别计算有限候选的非支配集合，再汇总配置入选频率。一个种子只有 0/1 两种结果，不称为稳定概率。训练均值的非支配集合与独立种子入选频率分列。

本轮执行器不把心理权重扰动混入跨种子波动。后续 OAT 必须保持同一实验目录结构，分别展示参数敏感性和随机不确定性；不能用二者混合的排名说明稳健性。

运行结果允许出现 λ/a 对收入无明显影响、收入与留存权衡、某支援无收益或新模型不改变排序等情况，按结果报告。

## 8. 执行命令

先完成四角、基准和 2×2 模块对照；默认两种观察期、两组种子共 32 个独立运行：

```powershell
.\.venv\Scripts\python.exe tools\run_research_v2.py --suite smoke --players 200 --workers 4
```

执行全部 25 个候选及 2×2 模块对照，共 112 个独立运行；已完成且口径相同的运行直接复用：

```powershell
.\.venv\Scripts\python.exe tools\run_research_v2.py --suite search --players 200 --workers 4
```

扩大人口与种子时使用独立输出目录：

```powershell
.\.venv\Scripts\python.exe tools\run_research_v2.py --suite search --players 1000 --seeds 1101 1102 1103 1104 1105 9101 9102 9103 --horizons 10 20 --workers 4 --out outputs\research_v2_n1000
```

`--suite smoke` 与 `search` 是候选运行范围，均执行完整模块对照；不是改变科学公式的开关。普通网格采用汇总日志；四角和基准及其模块对照采用全量日志。

## 9. 适用范围

公开通关样本缺少失败尝试、未投稿玩家和随机购买分配。经验成绩锚点带有选择、装备与操作等混杂，支持参数区间和机制分类，不直接识别付费因果转化。

行为权重、续订/直购意愿和流失公式仍需外部数据或范围敏感性检验。固定队列不含获客、回流和运营成本，累计现金不是游戏全盘流水预测，也不等于完整 LTV。

购买规划器只评估当前卡池的部分获取结果，不预知未来排期，也不求解跨期最优囤抽。囤抽记忆 h 是随经历调整的行为状态，不能据此识别玩家的理性预期或 Coase 式等待均衡。

正式比较必须同时阅读短长期现金、核心/总体留存、付费中间态、旧资产累计可用性和右删失，避免用单一末期指标替代研究问题。
